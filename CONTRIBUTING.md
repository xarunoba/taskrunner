# Contributing

## Bug reports

Include the output of `taskrunner --version`, the command or key sequence, and the expected and actual behavior. For TUI problems, include the terminal size and a screenshot when useful. Remove secrets from task definitions, job output, and environment values before sharing them.

## Pull requests

- Keep each change focused. Explain the problem it solves and any compatibility impact.
- Review the code you submit and be prepared to explain its behavior and failure cases, including code produced with AI tools.
- List the checks you ran and their results. Follow the [development checks](README.md#development); for behavior fixes, include a reproduction and a regression test when practical.
- For TUI changes, include the terminal sizes and keyboard and mouse paths you exercised. Include a screenshot or recording for visual changes.

Passing automated checks does not establish correctness or licensing. Review both before submitting.

## License

By submitting a contribution, you agree that it is licensed under the project's [MIT License](LICENSE). You must have the right to submit the contribution and must preserve any third-party copyright and license notices.

## Code provenance

Submit only code that you wrote or that you are authorized to contribute under terms compatible with the MIT License.

For AI-assisted contributions:

- You remain responsible for the code and its provenance.
- Review generated output before submitting it.
- Do not submit output copied from, or substantially similar to, third-party code with an unknown or incompatible license.
- Disclose material AI assistance in the pull request.
- Identify the source and license of third-party code, documentation, or other material supplied to the model or incorporated into the contribution.

If provenance or licensing is unclear, do not submit the material.
